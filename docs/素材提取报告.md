# 游戏素材提取 · 第一轮报告（2026-11-09）

## 结论一句话

菜单贴图包**能完整解出来**（工具已跑通，1247 张，带游戏原始文件名），
但里面**只有四类图**：道具图标 / 教学截图 / 八职业立绘 / 剧情插画。
**夜王头像、世界地图、UI 图标这三样不在菜单包里** —— 要么在加密的 data*.bdt 里，要么本来就是 3D 模型/矢量 gfx。

## 已跑通的链路

```
menu\00_solo_h.tpfbdt (475 MB, BHF4/BDF4 binder)
  → 扫 "DCX\0" 切片 1247 段
  → SoulsFormats.DCX.Decompress（Oodle KRAK，oo2core_9_win64.dll）
  → SoulsFormats.TPF.Read
  → Texture.Headerize() 出 DDS（DXGI 98 = BC7 1198 张，DXT1 49 张）
  → Pillow 转 PNG（BC7 能读）
```

工具：`tools\menuextract\`（dotnet exec menuextract.dll <bdt> <out> [--names]）
产物：`work\menu_h\*.dds`（原始 1210 MB）、`work\png_h\*.png`（512px 浏览版）

## 解出来的四类（文件名即游戏内名）

| 前缀 | 张数 | 内容 | 对编辑器有用吗 |
|---|---|---|---|
| MENU_Knowledge_* | 1127 | 道具/装备图标（药瓶、武器…） | 基本没用 |
| MENU_Tuto_* | 59 | 教学截图（游戏内实拍） | 没用 |
| MENU_Character_49xxx | 48 | 8 个职业 × 6 种姿势的立绘 | 不是夜王，没用 |
| MENU_ScenarioIllust_* | 13 | 剧情素描卡 | 没用 |

另外 `20_solo_dlc01_h` 39 张（DLC 同四类）、`00_solo_l` 同 1247 张低清版。

## 找不到的三样（需要补）

1. **夜王头像 ×8**（+ DLC）—— 游戏里夜王选择界面用的是 3D 模型，没有 2D 立绘。
2. **世界地图 / 缩圈示意** —— 没在菜单包；NR 的地图界面多半是 3D 或 gfx 矢量。
3. **UI 图标**（pin、按钮、状态灯）—— `.gfx`（FWS，Scaleform）里几乎不含位图（抽 10 个只 1 个 JPEG），是矢量图形。

## 卡住的地方（诚实记录）

- `Game\data0..3.bhd` / `dlc01.bhd` **是 AES 加密的**：magic 不是 `BHD5`，SoulsFormats 报
  `InvalidDataException: Read ASCII: <乱码> | Expected ASCII: BHD5`。
- 但 `Game\_DSAS_CACHE\data*.bhd` 里是**已解密的 BHD5 明文头**（DSAS 工具缓存），说明有钥匙可解 —— 下一步可以顺着 DSAS 找解密方式，再扫 bdt 里的 TPF（5 GB × 5 个包，需要后台跑）。
- 即使解开，也只能拿到"有贴图的那些"；夜王若真是 3D 就还是没有。

## 命名规则（给编辑器用）

运行期按 id 找图，找不到就显示编号，永不报错：

```
assets\boss\<夜王id>.png
assets\map\<mapId>.png
assets\icon\<iconId>.png
assets\ui\<动作名>.png
```

缺图清单导出 CSV，把图丢进去即生效（文件名 = id）。

## 备选方案

1. 自己截图 / 找图丢进 assets（后续再补）。
2. 顺着 DSAS 拿 data*.bdt 解密钥匙，全库扫 TPF（后台跑，能解多少算多少）。
3. 夜王实在没图 → 用夜王 id 数字 + 名字首字，符合"没图用编号"规则。
