## 一、现在能做什么（v1 已通）

1. 打开任意 `regulation.bin`（或它的所在文件夹，自动列出里面的 bin）
2. 选一个夜王 → 自动锁该夜王的**官方第一个种子**当模板（`patternSetId = boss×10+0` 的第一个 patternId）
3. 地图上只显示 **47 个校准过的建筑位**（蓝=大 / 绿=小 / 灰=未知）
4. 点一个建筑位 → 底部只列**官方种子在这个位置真的用过的建筑**（照抄，不猜）
5. 选建筑 → 选属性变体（`variationId` 0 基）→ 加入草稿 → 图上出现「图标 + 白圈 + 右下角属性徽章」
6. 实时校验（绿/黄/红），「写回」= 复制 param → 追加四张表的行 → regtool pack → 再解包对账 → 备份 `.prev_<时间戳>` → 覆盖
7. 写回后给出 `patternId`，可以拿 eventFlag 去游戏里验证

启动：双击 `启动.bat`（起 8777 再开浏览器）；关掉用 `停止.bat`。

## 三、数据链路（已实测确认）

```
选夜王 → 随机种子
  └ LotResultMapPatternFlag（rareMap + targetBoss 筛）
       + MapPatternSet.patternCount（容量，严格累加）
            └ 确定 patternId
                 ├ LotResultPlayAreaParam（缩圈 + 夜晚 BOSS，与 pid 严格 1:1）
                 ├ LotResultSmallBaseAndSpot（逐行规定摆哪几个 attachId）
                 │     ├ attachId  → SmallBaseAndSpotAttachPoint（坐标：world = grid*256 + 128 + pos）
                 │     └ smallBaseMapId → SmallBaseMapVariationParam（建筑本体 + 属性变体）
                 │            └ 图标：SmallBaseAndSpotDefine[含该 tile].worldMapPointIconId1
                 │                   → WorldMapPointIconParam[id].iconId
                 │            └ 属性：variationIconId_{variationId+1}（要 variationValue_{variationId+1} ≠ 0 才算存在）
                 └ LotResultMapPatternFlag 的 eventFlag（事件，照抄模板，先不换）
```

要点：

- `_name`（`Tile: xxx`）是**地块名**，不是建筑；建筑看 `smallBaseMapId` 指向的 variation 表
- `patternCount` 是容量，**不是权重**；新增 patternId 直接放表尾、不用重排（已验证）
- `patternId` 全局连续；现有 set 1096 声明 5 实际只有 1200 → 新种子用 1205
- `AttachPoint` 的 `pad`（行内 +7，paramdef 里是 `dummy8 pad[1]`）**0 = 普通地形，非 0 = 特殊地形**；562 行里 152 行是特殊地形
- `attachId ≥ 1000` 是地下孪生槽，不属于普通地图

## 五、踩过的坑（精华，别再踩）

1. **PowerShell 传中文路径给 python 会变 `??`** → 测试用 ASCII 路径或相对路径；页面端 UTF-8 不受影响
2. **PowerShell 里替换含 `${...}` 的 JS** 会把模板字符串写坏（页面出现字面量 `n`）→ 用 edit / write
3. **`ParamDir.rows()` 返回 dict 不是 list**，遍历要 `.values()`
4. **读带 BOM 的 .py** 用 `utf-8-sig`，否则 `SyntaxError: invalid non-printable character U+FEFF`
5. **改 canvas 尺寸会清空画布**：resize 回调里必须 `fit(); draw();`，只 fit 会出现「一片空白」
6. **`ctx.drawImage` 遇到破图会抛异常**，整个 draw 循环中断（表现为「地图有点、pin 全无」）→ 先判 `naturalWidth>0`
7. **坐标是 2 元组 (x,z)**，用 `world[2]` 会 NaN，而 canvas 对 NaN 静默不画
8. **格号换算**：`world = grid*256 + 128 + pos` → `floor(world/256)`；减 center 会差一格（同一段逻辑在仓库里有两份，改一份不够）
9. **视觉纠正只改渲染层副本**，绝不碰写回用的原始行；要整体调就调 OX/OZ，别单点挪
10. **服务端和前端各算一遍位置** 必然对不上 → 服务器算好 `px/py` 下发，前端只画
11. **`dynamic` 编译不过**（-nostdlib 缺 Microsoft.CSharp）→ Smithbox 的 API 一律走反射
12. **Oodle**：`oo2core_9_win64.dll` 必须放在 exe 同目录（fsx 工具必须在该目录下运行）

   「variationId N 在 SmallBaseMapVariationParam 里没有这一档 —— 能放，但游戏里可能没属性 / 表现异常」。
   手输的档位若**正好是官方某一档**（例如 3410 的 3 = 冻伤），就直接选中官方那格，不留虚线格、不报黄字。
4. 选好之后点「加入草稿」，草稿行写的就是这个 `variationId`；`Project.tile_variants` 校验照旧会给黄灯
   （`tile 3220 没有 variationId=9 这一档（有 [0, 1]）`）。
5. 底部建筑图标上的属性小徽章跟着变（`renderPicker` 重画）。

**新接口**：`GET /api/variant?tile=<smallBaseMapId>&v=<variationId>`
→ `{tile, variationId, slot(=v+1), exists, value, icon, attrName, hasRow}`。
`exists` 判定沿用老规矩：`variationValue_{slot} ≠ 0` 才算有这一档；`variationIconId_{slot}=0` 就是无属性。
