# 下一步规划（第二阶段）

> 写于 2026-11-10。v1（只看 + 摆点 + 属性变体 + 写回）已验收，下面是把「能用」变成「好用 + 真生效」的四条线。

## 现状

| 能做 | 不能做 |
|---|---|
| 打开 bin / 选夜王 / 新建草稿 | 换 `eventFlag`（目前照抄模板） |
| 47 个校准锚点上摆建筑 | 改缩圈与夜晚 BOSS（照抄模板） |
| 选 `smallBaseMapId` + `variationId`（属性） | 改 `modifier / modifierSet`（黑盒） |
| 写回并五项对账 | 验证游戏里真的刷出来 |

## 四条线

### A. 游戏内验证（最高优先级）
**目的**：证明「新建 set + 新 pid + 写回」这套理论在游戏里成立，否则后面全是空中楼阁。
- 做法：用 `D:\nrtest\base.bin` 建一个种子（例如 boss 2 + 3 个地点），写进 `Game\moremap\regulation.bin` 的副本，进游戏看：
  1. 新种子能不能被随机到（可能需要调 `weight` / `patternCount`）；
  2. 地图上的点是不是我们摆的；
  3. 属性徽章是不是对的。
- 风险点：`patternId` 的分配是否要跟「声明区间」严格对齐（set 1096 少 4 个 pid 那个坑）。
- 需要做：进游戏跑几局，回报现象。

### B. eventFlag（第二优先）
**目的**：让新种子能有自己的事件（入侵时机、宝箱），不再和模板共用。
- 现状：`LotResultMapPatternFlag` 里每个 pid 有 9~14 行变体，差在 `eventFlag` + `modifierSet`。
- 做法：把「事件变体」做成下拉，选一行照抄；再单独给一个「换 flag 号」的输入框；同时校验 flag 是否已被别的 pid 占用。
- 需要：确认 flag 号段怎么分配（有没有官方保留区）。

### C. 缩圈 / 夜晚 BOSS
**目的**：新种子能选自己的 `playArea` 与夜王。
- 现状：`LotResultPlayAreaParam` 与 pid 严格 1:1，直接抄模板。
- 做法：列出该夜王用过的 playArea 组合给选；选了就复制那一行。
- 难度：低（数据已摸清）。

### D. 界面收尾
- 草稿点列表可排序 / 逐个删除 / 撤销重做
- 导出这次改动的 JSON（给别人复现）
- 「这一格还剩几个空位」提示

## 建议顺序

1. **A 先做一个最小验证**（1 个种子、3 个点），进游戏跑一次
2. A 通过 → **B**（eventFlag），同时 C 顺手做掉（数据简单）
3. D 穿插做，不阻塞

## 需要拍板

- A 的验证要不要现在做？（要的话先出一份「改哪个 bin、怎么备份、怎么看结果」的步骤单）
- B 的 flag 号段：沿用模板那套，还是指定一段没用过的？
