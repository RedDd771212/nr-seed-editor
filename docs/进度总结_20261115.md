## 二、实测定下的规则（下次直接用，别再试错）

1. **patternId = ⌊setId/1000⌋ × 1000 + 组内前缀和**（两份 bin 101/101 验证）；**组之间互不影响**
2. 新 set 一律放表尾（id = max+1），落 1000 组
3. `patternCount` 是派生值 = 该 set 实际 pid 数，不手填
4. set 级池子（`*_Count`）按「个数」维护；官方自己也有 28 处对不上（DLC 组写成 1/1）
5. `mapIndex` 在官方数据里**唯一但不按文件顺序**；克隆保留原值、新增取 `max+1`
6. `rareMap 0..5` ↔ 地图类型行 `eventFlag = 7600+rare` / `modifier = 10+rare`
7. `2xxx`（2000–2199）是空壳 tile（只有 spot 引用，无 variation/define）
8. DLC 种子用 `21xx` 一族 attachId，与校准池的 `1xx` 是同一个地方（减 2000 对应）
9. 现存化石：`[Custom] 1096`（pid 1200）的 mapIndex 全 0，按规则是坏数据
10. 行序可重编：flag/area/spot 三张表的行 id 没有任何表引用，可按 pid 排序 + 重编号；**set 表不能动 id**
